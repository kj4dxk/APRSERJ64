APRSIS64 tactical visual QA - 2026-11-20 (continued into Nov 21 UTC)

METHOD
Interactive Windows checks using the actual portable app, native screenshots,
mouse and keyboard. Isolated build/Tactical-Visual folder, local TCP APRS-IS and
simulated TEXT RF port, local HTTP weather fixture. Real pdeffenb raster tiles.
Synthetic packets stayed on loopback. Desktop user settings/history were isolated.
Main window normal and maximized; settings and tools inspected with scrolling.
Local screenshots are in outputs/visual-qa-tactical, excluded from Git.

FIXES
- Display/tactical preference saves no longer restart APRS/radio connections,
  discard heard stations or restart initial-beacon timers. Changes affecting the
  QRU subscription filter still reconfigure the connection.
- Tactical/display changes retain map camera position and zoom; source/renderer
  setting changes still recreate the map as necessary, including radar/offline.
- Overlay layer IDs follow stable style identities instead of changing indexes.
- Geometry uses actual current time when recalculated, not the last five-second
  timer tick. Fresh DF/path reports no longer briefly disappear as future-dated.
- QRU tool distinguishes the object responder from the separate text kiosk and
  identifies the relevant settings pages.
- The initial QA startup error was a fixture encoding/newline error, corrected
  locally. It did not involve the user's Desktop settings.

LIMITS
Representative interaction paths for each new capability were exercised; this is
not an exhaustive combination of all settings, geometries, sizes and protocols.
No physical GPS/TNC/radio was attached. DX uses simulated TEXT input, not measured
RF propagation. Public QRU servers and live NWS geometry were not used for these
checks. Estimates do not validate terrain-aware propagation. Upstream LWJGL Unsafe
and no-provider SLF4J warnings remain nonfatal.
